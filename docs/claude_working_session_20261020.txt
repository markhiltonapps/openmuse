1. Leaner chat
- Where the tokens go (measured with the test fixtures): a chat call is ~26,000 tokens before
  any conversation (7,000 of instructions, 19,000 of tool definitions, 89 tools). The rest is
  the person's own context and the conversation.
- The chat now runs on the quick worker model (Haiku 4.5 on Railway) unless CHAT_MODEL names
  another: `ModelChoices.serverModel` (chat: CHAT_MODEL, else WORKER_MODEL, else MODEL), with
  `config.chatModel` and the same rule in `service.modelFor`'s fallback. First attempt edited
  only modelFor, which the real server never reaches (agent.models is always set): caught by
  reading ModelChoices before trusting the change.
- The conversation kept word for word is now 40,000 characters, summarized sooner (chat-summary
  LIMIT 40,000, TAIL 20,000; was 100,000 and 50,000): ~10,000 tokens instead of up to ~25,000.
  Together: ~45,000 tokens a call (was ~70,000) at half the price per token, about 0.32 of
  before, so a message goes from ~4.8¢ blended to ~1.5¢. THIS IS A PROJECTION; confirm from
  Railway's "Model call: chat" lines after the deploy.
- Tradeoff, told to the owner: Haiku is a step down from Sonnet for hard, many-tool requests.
  To put the chat back: set CHAT_MODEL (e.g. the Sonnet name) on the api service in Railway and
  choose Deploy. The Models card still overrides everything once OpenRouter is set up.
- Tests: openrouter.test.ts's picks test now expects the chat on the worker model; a new test
  covers CHAT_MODEL, the worker fallback and the main-model fallback. chat-summary tests pass at
  the new limits. Help (admin-models), .env.example and the README say how the chat's model is
  chosen.
