== All-day sleep ("sleep when idle", built 2026-11-13) ==
Setting `sleepWhenIdle` (default on; only matters with the battery saver): server DeviceSettings, describeSettings, manage_devices `sleep_when_idle`, idle fact `nap`.
Firmware (neddy_device.ino): once the screen has been dark 60 s on battery (not charging, no USB, not recording, not talking, mode ready), `napSleepWifi()` closes
the socket and turns Wi-Fi off. While Wi-Fi is off and the screen is dark the loop ends each turn in `esp_light_sleep_start()` (100 ms timer + BOOT low wakes), so touch, the PWR
key (the power chip latches it), the raise detector and BOOT are all still looked at by the usual loops, just ten times a second. BOOT, a touch-and-hold, a recording to send,
USB power, the saver/sleep setting changing, or a menu change that must reach Neddy (queued in pendAnim/pendFace/pendVol) call `napWake()`, and the existing join/connect path runs
("Joining Wi-Fi", about 2-4 s). A raise, a tap or PWR shows the clock/menu without turning Wi-Fi on. The link code (Wi-Fi, pairing, socket) moved out of loop() into linkTurn() (no change in what it does); it is skipped while napWifiOff.
Expected: ~5-8 mA asleep (not measured; unknown: how much the dark AMOLED driver, PSRAM, IMU and codec chips draw). Real-board checks: server log shows "disconnected (code 1000)" about
2-3 minutes after the last touch and "connected" after BOOT; battery % curve over an hour; press then wait for ready then talk; recording after a long quiet; plug in USB while it sleeps (should wake within ~5 s).
NOT compiled (no Arduino toolchain here). Tests: tests/device-idle.test.ts 11 pass (new: sleep_when_idle setting + `nap` fact), tests/help.test.ts. Help: Battery paragraph.
Known limits: pull-only (no heads-ups while asleep); the press that wakes it is used up joining Wi-Fi, so press again once it says ready; light sleep stops the USB serial monitor (it is skipped while USB power is present).
Possible next steps if still not enough: put the AMOLED driver in its own sleep mode (command 0x10) while dark, lower the CPU to 80 MHz, let the IMU raise detector use its own interrupt.
