OpenRouter: cut LLM costs (Oct 6) — step 1 (investigation) done, nothing changed yet
- Owner's goal: route model calls through OpenRouter. Manager / hard work on
  openai/gpt-6.1-sol with reasoning effort "high" (never the -pro variant); simple routine work on
  a cheap fast model such as DeepSeek V4.1 Flash with low effort. The model for each job a
  config setting. Prompt caching, short context (under 272k input tokens on GPT-6.1 Sol), max
  output tokens per job, cost logged per call, one retry on the stronger model. The current
  provider setup stays as a fallback. Small real test calls first; ask before production changes
  or spending beyond small tests. Key only from OPENROUTER_API_KEY, never in code, logs, commits
  or chat.
- How models are called today:
  - TanStack AI through CopilotKit (adapters: Anthropic, OpenAI, Gemini), chosen by
    provider/model strings: MODEL (chat agent, also a call's hand-overs; a Claude model) and
    WORKER_MODEL (background jobs and routines, chat summaries, Ideas, bookings from emails;
    anthropic/claude-haiku-4-5-20251001 since Sept 30). Adapter switch:
    apps/server/src/engine/tanstack-agent.ts adapter(); settings: apps/server/src/config.ts.
  - Direct Anthropic Messages API calls (ANTHROPIC_API_KEY) for Anthropic-only features: web
    search (Claude's web_search tool, WEB_SEARCH_MODEL, Haiku by default), the code sandbox
    (code execution + Files API, CODE_MODEL, Sonnet 5 by default), pictures, recipes, ChatGPT
    import and avatar design (VISION_MODEL / AVATAR_MODEL, else the chat model).
  - OpenAI Live API (gpt-live-1) for live voice calls.
  - Movable to OpenRouter: chat agent, background jobs, summaries, Ideas, bookings from emails.
    Staying put unless replaced separately: web search, code sandbox, live voice.
- OpenAI-compatible base URL: MODEL=openai/<id> + OPENAI_BASE_URL already reaches a gateway,
  but that adapter (openaiText) speaks OpenAI's Responses API, reads OPENAI_API_KEY, and sets
  the base URL for the whole app; caching markers are only added for anthropic/ models. The
  installed @tanstack/ai-openai also has a Chat Completions adapter (createOpenaiChatCompletions)
  that takes its own key and base URL and reports cached tokens: an "openrouter/" provider in
  adapter() is about 15 lines, no new SDK.
- Also found:
  - Usage and cost are stored per person and per kind (usage.ts), but the price table has no
    OpenRouter models, OpenRouter's reported cost isn't used, and nothing logs per call.
  - No max output tokens or reasoning effort is set on agent calls.
  - Caching bug: a background job's instructions start with the current time ("It's …") ahead
    of the long fixed instructions, so the cached prefix breaks every minute. Moving the time to
    the end saves money on Claude too.

- Server:
  - Adapter (engine/tanstack-agent.ts): a new "openrouter/vendor/model" provider, using the
    installed Chat Completions adapter (createOpenaiChatCompletions) on OPENROUTER_API_KEY and
    https://openrouter.ai/api/v1 (OPENROUTER_BASE_URL overrides). No new SDK; anthropic/ stays.
  - model-choices.ts: three jobs.
    - Chat: GPT-6.1 Sol, effort high, up to 16K out.
    - Background jobs and routines: GPT-6.1 Sol, effort medium, 32K out.
    - Simple jobs (chat summaries, Ideas, bookings from emails): DeepSeek V4.1 Flash, effort low,
      4K out (8K at medium, 16K at high, so thinking never crowds out the answer).
    - The picks apply only when OPENROUTER_API_KEY is set; without it, every job stays on
      MODEL / WORKER_MODEL (Claude), as before.
    - The admin's choices are saved in system/model-choices. "server" means the server's model.
      "-pro" models are refused.
  - Calls: chat (conversation.ts), jobs (model.ts) and simple jobs (service.ts) ask
    service.modelFor(job). OpenRouter calls send reasoning.effort and max_tokens, and drop the
    oldest messages past about 250K estimated tokens (fitContext; GPT-6.1 Sol's price doubles
    past 272K).
  - A simple job that comes back empty is tried once on the chat's model (complete's `stronger`).
  - Caching fix: a job's instructions had the time ("It's …") ahead of the long fixed text. It
    now comes at the end, so the fixed instructions are a shared, cacheable start across runs.
    Within one run the prompt never changed, so this helps between jobs and restarts, not every
    call. (Corrects the earlier note.)
  - Usage (usage.ts):
    - Per-day totals in each person's time zone (usage-days), for Today and the last 7 days.
      All time adds up every month.
    - OpenRouter prices, with their own cache-read prices.
    - modelName drops "openrouter/" and the vendor.
    - fromTanstack subtracts cache reads for OpenRouter calls.
    - One log line per call: "[OpenMuse] Model call: <job> · <model> · read N (M cached) · wrote
      K · $cost".
  - Routes:
    - GET/POST /api/models (admin).
    - /api/usage adds periods and the three jobs' models.
    - /api/usage/people adds everyone's periods.
  - Chat: a read-only ai_costs tool ("How much has the AI cost this week?"); the admin also gets
    everyone's totals.
